BMad Chat UI, Forged

A half-idea about copying another app's multi-agent office arrived here as a scoped, evidenced plan for talking to BMad personas across every company project — after three real pivots and one killed architecture.

01 What survived

A chat-app UI for talking to BMad personas across your company's projects — one room per project, each persona (Mary, John, Winston, Amelia, Sally…) its own persistent contact, party mode as a group chat. It's a skin on real BMad/Claude-Code execution, not a new agent engine, and it inherits a real, evidenced fix for a bug that's been quietly breaking @ shortcuts, memory, and artifact routing across your projects.

02 How it got here

Started as

Clone Munder Difflin's architecture for BMad — separate CLI processes per agent, file-based mailbox, office-floor visualization.

Pivot

Rejected the separate-process hive. BMad personas stay running as skills inside real sessions — nothing to fork there.

Checked

Evaluated Munder Difflin's paid tiers (Free / Pro $150/yr / Teams $39/seat) against this idea. Killed — not a sellable product, and Teams' only real moat (cross-device messaging) doesn't apply here anyway.

Reveal

The actual problem wasn't visualization — it was coordinating BMad across projects that can't have BMad installed. bmad-hub already exists and attempts this.

Diagnosed

Read bmad-hub's own RFC. Found a self-documented known limitation: session cwd is a symlink dir, not the real checkout, so @ resolution silently fails. Root cause, not a UI gap.

Pivot

"I want it to feel like a chat app with real people" — named plainly as interface excitement, not an unmet capability. Chose the cheap path: a chat skin over real execution, not a rebuilt runtime.

Landed

One room per project, each persona a persistent contact, sync/routing correctness as invisible foundation rather than its own dashboard.

03 Locked decisions

Execution

Real BMad-in-Claude-Code underneath. The chat UI renders it; it does not reimplement agent execution on a separate stack.

Root fix

Launch sessions with cwd set to the real project checkout, not a symlink directory. Overlay canonical skills/_bmad via symlinks excluded through .git/info/exclude — never a committed .gitignore.

Scope

Context resolution and routing correctness are plumbing, not a product screen. The chat UI is the only surface; sync state shows as inline system messages.

Structure

One room per project, not one cross-company thread — matches how memory and context are already scoped.

Cast

Each BMad persona is its own persistent contact per project. Party mode becomes a group chat room with several persona contacts present.

License

FOSS release. No paid tiers, no monetization planning.

04 Rejected, and why

Killed

Munder Difflin's process-per-agent hive (node-pty, mailbox, GOD orchestrator, office floor) — the wrong-shaped fix for a single-session system.

Killed

Paid tiers modeled on Free/Pro/Teams — no sellable-product intent, and the one paid feature with a real moat (cross-device messaging) doesn't map onto this scope.

Killed

A standalone sync/status dashboard — absorbed into the chat UI as inline system messages instead of its own screen.

Killed

GitHub sync as a requirement — bmad-hub is already a normal git repo with a remote; plain git already covers it.

Passed over

A full custom agent runtime on the Agent SDK, independent of Claude Code — more capability than the actual want (interface feel) justified.

05 Open for the next phase

Technical

How bidirectional real-time chat is actually driven: pty-wrapping a real Claude Code process, vs. driving sessions via the Claude Agent SDK's structured message stream.

Home

Whether this extends bmad-hub in place (shares its registry, canonical skills, per-project storage) or lives in a fresh repo. Leaning toward extending — not firmly locked.
